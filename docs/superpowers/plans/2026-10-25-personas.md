# Personas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every project runs under a persona (its own Claude login, GitHub login on one host, and commit identity), set up through a first-run wizard and managed in a new Management view, together with fleet-wide agent instructions and settings.

**Architecture:** The daemon owns personas (SQLite rows plus one folder per persona holding `claude/` and `gh/` config dirs) and builds a per-persona environment that is applied to agent tmux sessions and to the daemon's own clone/fetch. Login status comes only from the `claude` and `gh` CLIs. The GUI runs the interactive logins (in a terminal emulator, or by piping a PAT into `gh`), gates the board until one persona is ready, and adds a Management view (Personas, Instructions, Agent settings), a persona switcher in the drawer, a persona dropdown in New project and a persona filter on the board.

**Tech Stack:** Rust 2021, tokio, axum, sqlx (SQLite), serde, ts-rs, utoipa, eframe/egui, egui_kittest.

**Spec:** `docs/superpowers/specs/2026-10-25-personas-design.md`

## Global Constraints

- Work in the worktree `../fleet-board-personas` on `feat/personas`, based on `main` at `074dc6d` (Projects view merged). Other sessions share the main checkout.
- Projects view vocabulary applies: `Status::Stopped` (no `Dead`), Stop and Archive (no Kill), a `projects` table whose records outlive their agent. A persona belongs to the project record as well as the live agent.
- **Commit steps need Antonio's go-ahead for this run** (CLAUDE.local.md: never commit unless he asked in the conversation). Stage only your own files by path; never `git add -A`.
- Commit subjects: Conventional Commits, imperative, under 50 characters (`feat(daemon): …`, `feat(gui): …`, `feat(api): …`, `docs: …`). Commit messages end with the session's attribution lines.
- fleet-manager never reads, copies, logs, stores or puts in argv/env a Claude or GitHub token. Login status only from `claude` / `gh` CLI exit codes and output.
- A missing, draft or broken persona fails loudly; nothing ever falls back to the ambient login (`~/.claude`, `~/.config/gh`, the user's git credential helpers).
- Nothing is written into the user's own checkouts' `.git/config`; git settings go in as `GIT_CONFIG_COUNT/KEY_n/VALUE_n` env.
- Persona folders are mode `0700`: `<personas_dir>/<id>/claude`, `<personas_dir>/<id>/gh`.
- Default `personas_dir`: `~/.local/share/fleet-manager/personas`.
- Provider-neutral naming for new keys and types (ROADMAP): `gh_command`, `agent_config`, not `claude_*` except where it is Claude's own variable.
- The web UI stays frozen. It must still type-check and build (`pnpm --dir web test && pnpm --dir web build`); a spawn from it without a persona is rejected with the missing-persona message.
- Run `cargo fmt --all` and `cargo clippy --workspace --all-targets -- -D warnings` before each commit; `./build.sh` regenerates TS types (`cargo test -p fleet-api --test contract ts_bindings_export`); commit the regenerated `web/src/api/generated/*` with the API change that caused them.
- `gh` becomes a requirement (README). It is a single binary and works air-gapped against GHE.

## Review Focus

1. **Persona names and hosts typed loosely**: `"Rodeo FX"`, `"https://GitHub.com/"`, `"rodeofx.ghe.com:443"`. Expected: id `rodeo-fx` (unique, `-2` on clash), host normalised to `github.com` / `rodeofx.ghe.com`. Tests in Task 3.
2. **Repo URLs whose host differs only in case, port, `www.` or a trailing `.git`/slash**: `https://GitHub.com/x/y.git` under a `github.com` persona is accepted; `http://` (no TLS) on the same host is accepted only if the user typed it (git decides); `git@github.com:x/y` is refused as SSH. Tests in Task 4.
3. **Login broken after setup** (gh token revoked, Claude logged out): spawn on that persona fails before anything is created, with a message naming the persona and which login; `ready` stays true and the persona shows the warning. Tests in Task 5.
4. **Agent settings with a reserved env key or a deny on fleet's own tools** (`GH_TOKEN`, `CLAUDE_CONFIG_DIR`, `deny: mcp__fleet__request_repo`): rejected on save with a message naming the key/rule; a hand-edited invalid `settings.json` makes spawn fail with that message rather than run with half the settings. Tests in Task 6.
5. **Deleting a persona that has projects, including stopped ones still on the board**: refused (409) with the count of its running and stopped project records; archived records do not block (they keep the persona id as a label). Tests in Task 3.

  - `GET /api/repos?persona=<id>` → only that persona's repos (no param → all, with `persona` set on each `RepoInfo`); `FleetClient::repos_for(persona: &str)`.
