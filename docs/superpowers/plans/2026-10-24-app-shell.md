# App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `tracing`-based logger for the whole workspace, and a GUI restructured into a drawer + content shell
with switchable views, a Settings view (General / Daemon / Log) and an app-wide cycling footer message line.

**Architecture:**
- A new `fleet-log` crate owns the log line format, its parser, and a `tracing-subscriber` stack (file layer,
  in-process fan-out layer, stderr-if-terminal layer).
- The daemon, client and GUI log only through it. The GUI's footer and Log tab are fed from the fan-out, so
  "post a footer message" means "emit a `tracing` event with a `notify` field".
- `FleetApp` draws the drawer and footer itself and delegates header / main / detail to the selected `View`.

**Tech Stack:** Rust 2021, `tracing` 0.1, `tracing-subscriber` 0.3, `tracing-log` 0.2, `toml_edit` 0.25,
eframe/egui 0.37, `egui_kittest`.

**Spec:** `docs/superpowers/specs/2026-10-24-app-shell-design.md`. Read it before any task. Mockups (gitignored, read
from the main checkout): `/mnt/users/afrontino/fleet-board/.superpowers/brainstorm/825084-1792854790/content/layout-v5.html`.

## Global Constraints

- **New external crates allowed: `tracing-subscriber` (features `std`, `registry`, `env-filter` only, no `fmt`,
  no `ansi`) and `tracing-log`.** Nothing else. After Task 2, run `cargo tree -e normal --prefix none | sort -u`
  against the same command on the base commit and list every crate new to `Cargo.lock` in the task report:
  Antonio mirrors them into Nexus. `toml_edit` and `time` are already in the lock; do not add `time`
  (timestamps are formatted by hand, Task 1).
- **One way to log.** No `eprintln!`/`println!` for diagnostics in `fleet-daemon`, `fleet-client`, `fleet-gui`.
  Exceptions, kept on stdout/stderr: `--version` output, the daemon's `fleet-manager listening on …` line, and
  the daemon's fatal error at exit (also logged when the logger is up).
- **Line format (exact):** `<YYYY-MM-DDTHH:MM:SSZ> <LEVEL padded to 5> <target> <message>` then, per field,
  `\t<key>=<value>`. `\n`, `\r`, `\t` and `\\` in message and values are escaped as `\n`, `\r`, `\t`, `\\`.
  Example: `2026-10-24T14:09:55Z ERROR fleet_gui::app Could not start the agent: repo "web" not found\tnotify=error`.
- **Footer notice field:** `notify` with a string value: `"error"`, `"warning"`, `"success"`, `"info"`. Error goes
  on `error!`, warning on `warn!`, success and info on `info!`. No other way reaches the footer.
- **Default filter:** `warn,fleet_daemon=info,fleet_client=info,fleet_gui=info,fleet_log=info`. `FLEET_LOG`, when
  set, replaces it (an `EnvFilter` directive).
- **Files:** `<state_dir>/gui.log` and `<state_dir>/daemon.log`. Append, one `write` call per line.
- **Layout constants (in `theme.rs`, `pub mod layout`):** `HEADER: f32 = 40.0`, `FOOTER: f32 = 28.0`,
  `DRAWER: f32 = 200.0`. Drawer header and content header are both exactly `HEADER` tall; drawer footer and
  content footer are both exactly `FOOTER` tall. These numbers are the builder's to tune; the sharing is not.
- **Migration notes:** `migrate_legacy_dirs` runs before the logger exists (it may move the state directory the
  log file lives in). Keep it first, collect its notes, init the logger, then log each note with `info!`; drop the
  `eprintln!` of them.
- **Copy (exact):** brand row `fleet-manager`; nav `Kanban`, `Settings`; Settings tabs `General`, `Daemon`, `Log`; drawer footer `live` /
  `reconnecting…`, then `N agents` and ` · M need you` (M > 0 only; `1 agent`, `1 needs you` singular);
  General headings `Theme`, `Closing the window`, `Footer`, `Projects folder`; close options `Ask`,
  `Keep daemon running`, `Stop daemon`; footer checkbox `Keep errors and warnings in the footer until dismissed`;
  projects note `Applies to new projects only. Saving restarts the daemon; running agents keep going.`; history
  link `Open log →`; Log sources `App`, `Daemon`, `Both`.
- **Footer timing:** 4 s per message, 8 s for errors.
- **History:** last 10 footer messages.
- `docs/ui.md` is updated in the task that changes what it describes.

## Review Focus

1. **A multi-line or very long footer message** (a daemon error with a stack of context) must stay one line:
   truncated with an ellipsis, full text on hover. Test in Task 6.
2. **The same error repeating while it is looping** (an action retried, a failing save clicked twice) must not
   fill the queue: dedupe against everything queued, including the one on screen. Test in Task 6.
3. **The state directory is not writable, or `gui.log` cannot be opened:** the app still opens; the fan-out still
   feeds the footer and Log tab; one warning notice says logging to file is off. Test in Task 2 and Task 4.
4. **A large or missing `daemon.log`** when the Log tab opens: read at most the last 1 MiB of each file; a missing
   file shows `No daemon log at <path>` instead of an empty list. Test in Task 8.
5. **Projects folder Save with nothing to restart for, or a restart that fails:** the same path as the current
   root disables Save; a failed restart leaves the new config written, posts an error notice, and the Daemon tab
   offers `Restart daemon`. Test in Task 7.

  // messages.rs — no egui; time is seconds as f64, passed in
  pub struct Message { pub notice: Notice, pub text: String, pub time: i64 }
  pub struct Messages { /* queue, current + shown-since, history (10), sticky */ }
  impl Messages {
      pub fn new(sticky: bool) -> Messages;
      pub fn set_sticky(&mut self, on: bool);
      pub fn push(&mut self, m: Message, now: f64);      // dedupes on (notice, text) against queue and current
      pub fn tick(&mut self, now: f64);                  // advances after 4 s / 8 s
      pub fn click(&mut self, now: f64);                 // dismiss a looping one, else skip
      pub fn current(&self) -> Option<(&Message, bool)>; // bool = dimmed (queue empty, last one kept)
      pub fn position(&self) -> Option<(usize, usize)>;  // (i, n) while n > 1
      pub fn history(&self) -> &[Message];               // newest first, at most 10
